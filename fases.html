Evolución del proyecto

Fase 1 validada, Fase 2 en integración

Esta página organiza EcoHuella IA-Bio en dos partes: primero la validación del prototipo, el modelo y el diseño físico; después la integración funcional con aplicación móvil, backend, IA servida por API y EcoPuntos.

Fase 1

Prototipo, IA y diseño físico

La primera fase documenta y demuestra que la idea funciona: el sistema puede reconocer residuos, mostrar resultados y explicar su arquitectura.

  • Sitio web informativo publicado con las secciones principales.
  • Modelo MobileNetV2 entrenado para orgánico, reciclable y no reciclable.
  • Dataset CDMX preparado, dividido y evaluado con métricas del modelo.
  • Video de prueba del modelo de IA en la página de IA y métricas.
  • Materiales definidos: HDPE, panel solar principal y batería LiFePO4.
  • Diagramas de arquitectura, flujo de decisión y operación mecánica.
Ver test de IA
Fase 2

Vertical funcional con app, backend y EcoPuntos

La segunda fase acopla lo ya validado a un flujo real de usuario: abrir sesión, escanear el contenedor, clasificar el residuo, guardar el evento y entregar la recompensa.

  • App móvil en Expo y React Native con acceso demo.
  • Backend NestJS como entrada principal para la aplicación.
  • FastAPI con OpenCV y TFLite para ejecutar la clasificación.
  • PostgreSQL como fuente de verdad para sesiones, eventos y EcoPuntos.
  • Estados de sesión: activa, completada, cancelada y expirada.
  • Manejo de baja confianza, reintentos, idempotencia y errores operativos.

Alcance controlado

Límites del MVP para no inflar la complejidad

La Fase 2 debe demostrar el flujo completo sin prometer todavía todo el hardware automatizado en producción. El objetivo es probar integración, trazabilidad y experiencia de usuario antes de escalar el sistema físico.

  • Autenticación real queda fuera del MVP; se usa acceso demo.
  • No se almacenan imágenes completas como evidencia permanente.
  • La compuerta física puede seguir como demostración conceptual.
  • FastAPI queda detrás de NestJS, no expuesta directamente al usuario.
  • El flujo offline se deja para una etapa posterior.
