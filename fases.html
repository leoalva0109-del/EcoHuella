EcoHuella IA-Bio por fases

La presentación se divide en dos niveles. La Fase 1 reúne el prototipo, la IA y la documentación técnica ya construida. La Fase 2 muestra la integración funcional con app móvil, backend, sesiones y EcoPuntos.

Fase 1

Base técnica y visual del prototipo

Esta fase concentra el avance ya presentado: modelo de IA, diseño del contenedor, componentes físicos, evidencia de entrenamiento y documentación del flujo de operación.

Fase 2

Integración app, backend, IA y EcoPuntos

La segunda fase convierte el prototipo en un recorrido funcional: el usuario entra a la app, escanea el contenedor, inicia una sesión, recibe la clasificación y obtiene su registro de puntos.

Ruta funcional

Recorrido completo de usuario

La Fase 2 ordena la experiencia desde el celular hasta el historial del depósito.

01

Acceso demo

Entrada directa para presentar el flujo sin depender de autenticación real.

02

Home + EcoPuntos

Vista principal con saldo, actividad reciente y acceso al escáner.

03

Escaneo QR

La app identifica el contenedor y solicita una sesión de depósito.

04

Sesión activa

El backend controla vigencia, estado y duplicados durante el depósito.

05

Análisis IA

FastAPI procesa frames y devuelve clase, confianza y tiempo de respuesta.

06

Resultado

La app muestra clasificación aceptada, baja confianza o solicitud de reintento.

07

Historial

El usuario consulta depósitos, etiquetas, fechas y EcoPuntos obtenidos.

Backend y contratos

NestJS como centro de coordinación

La app conversa con NestJS; NestJS administra reglas, sesiones y comunicación con IA.

App

Expo / React Native

QR, sesión, resultado, puntos e historial.

API

NestJS

Estados de sesión, reglas de depósito e idempotencia.

IA

FastAPI

Recibe frames, ejecuta inferencia y devuelve respuesta estructurada.

DB

PostgreSQL

Conserva sesiones, clasificaciones, transacciones y puntos.

Servicio de inferencia

Clasificación preparada para la demo conectada

El modelo se integra como servicio para responder con rapidez y mantener trazabilidad.

Captura breve

El contenedor toma una secuencia corta de frames para analizar el residuo.

Selección de frames

OpenCV prepara las imágenes más representativas para el modelo TFLite.

Umbral de confianza

La respuesta distingue clasificación aceptada y baja confianza.

Respuesta estructurada

La API devuelve etiqueta, confianza, latencia y estado de la predicción.

Reintento controlado

Cuando la confianza no alcanza el umbral, el usuario recibe una salida clara.

Preparación para reentrenar

Los resultados agregados ayudan a detectar clases difíciles y mejorar el dataset.

Datos y recompensa

Sesiones, historial y EcoPuntos

La base de datos sostiene la trazabilidad del depósito y evita recompensas duplicadas.

Sesión de depósito

Registra contenedor, usuario demo, estado, creación y expiración.

Resultado IA

Guarda clase detectada, confianza y estado final de la clasificación.

EcoPuntos

Un depósito aceptado suma puntos mediante una transacción controlada.

Historial

La app recupera eventos anteriores para mostrar progreso del usuario.

Consistencia

La idempotencia evita que un mismo intento genere recompensas repetidas.

Auditoría técnica

Los registros permiten revisar latencia, errores y comportamiento del flujo.

Validación

Condiciones para cerrar la Fase 2

La entrega se valida con un recorrido completo y casos de error controlados.

Servicios disponibles

NestJS, FastAPI y PostgreSQL responden con estado saludable.

Flujo aceptado

QR, sesión, clasificación, resultado y EcoPuntos funcionan de inicio a fin.

Baja confianza

La app solicita reintento sin cerrar incorrectamente la sesión.

Estados de sesión

Activa, completada, cancelada y expirada se reflejan en backend y app.

Duplicados

El mismo intento conserva el resultado original y no suma dos veces.

Recuperación

Los errores de IA o base de datos dejan el sistema en un estado consistente.
