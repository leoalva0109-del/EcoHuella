Frontend

Implementación y recorrido visual de la app

Expo y React Native concentran navegación, estado de servidor, captura QR y representación de resultados sin duplicar reglas del backend.

Base técnica

Expo + React Native + TypeScript

  • Expo Router organiza las siete rutas funcionales.
  • TanStack Query administra consultas, caché y actualización.
  • El cliente HTTP usa fetch, timeout y errores normalizados.

Frontera de integración

NestJS es la única puerta de entrada

  • La app no consulta FastAPI ni PostgreSQL directamente.
  • La URL se configura mediante EXPO_PUBLIC_API_BASE_URL.
  • session_id y attempt_id se conservan solo durante el flujo.

Estado verificado

Conectividad LAN comprobada

  • Health checks de NestJS, FastAPI y PostgreSQL respondieron correctamente.
  • TypeScript, lint, bundle y rutas base pasaron verificación.
  • La evidencia visual móvil completa el recorrido del PoC.

Muestra, método y limitaciones

El umbral de 0.95 controla la aceptación operativa del PoC. No debe confundirse con la accuracy global ni interpretarse como desempeño de campo.

PoC actual

Región controlada + MobileNetV2

OpenCV prepara la captura y FastAPI ejecuta el modelo TFLite. LOW_CONFIDENCE se conserva como resultado válido.

Evolución prevista

YOLO + Jetson Nano

La detección de objetos, el edge definitivo y la actuación física se integran después de cerrar la vertical LAN.

Preparación

Entrenamiento

Transfer learning, data augmentation y fine-tuning parcial en dos etapas.

Validación

Accuracy, precisión, recall, F1 y matriz de confusión por clase.

Cierre de la Fase 2

El backend ya presenta 85.8% de cobertura verificada en su matriz M1. La Fase 2 se considera cerrada cuando las siete interfaces completan el flujo con datos reales y los casos accepted, LOW_CONFIDENCE, duplicado y fallo controlado se observan de extremo a extremo.

Condiciones objetivas para cerrar el PoC

<100 msobjetivo provisional de inferencia p95
  • Probar resultados accepted y LOW_CONFIDENCE.
  • Repetir attempt_id sin duplicar transacciones ni EcoPuntos.
  • Distinguir fallos de red, NestJS, FastAPI y PostgreSQL.
  • Conservar logs, health checks, historial y registros transaccionales.

La confianza de una predicción se registra durante la demostración, pero no sustituye las métricas globales de precisión del modelo.
